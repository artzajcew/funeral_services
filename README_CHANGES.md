# Изменения в FuneralApp

## Что реализовано
- Роли не используются в Java-моделях и SQL-схеме. Для существующей БД есть `src/db/remove_roles.sql`.
- Сортировка заказов по ID, клиенту, статусу, сумме или дате, по возрастанию/убыванию. Поля сортировки проверяются по whitelist.
- Статистика: общее количество пользователей; количество заказов за период; минимальная и максимальная сумма заказа за период; выручка за период.
- CRUD для `Order`: создание (уже использовалось при оформлении, теперь возвращает ID), список, получение по ID, обновление, удаление. Позиции заказа удаляются каскадно согласно `schema.sql`.
- В `GuestMenu` добавлен пункт доступа к меню управления, чтобы статистика и CRUD были доступны без ролевого разделения.

## Правило расчёта выручки
В текущей схеме нет отдельного статуса оплаты. Поэтому выручка считается как сумма `total_cost` заказов со статусом `COMPLETED` за указанный период. Количество заказов и min/max считаются по всем заказам за период, включая отменённые. Если бизнес-правила другие, фильтры можно изменить в `OrderDAO.getStatistics`.

## Как применить
1. Скопируйте файлы из архива поверх проекта или сравните их с исходниками.
2. Для существующей БД выполните `src/db/remove_roles.sql` (если колонка `role` существует).
3. Для новой БД используйте `src/db/schema.sql`. **Он удаляет существующие таблицы перед созданием**, поэтому не запускайте его на базе с нужными данными.
4. Убедитесь, что настройки подключения в `src/db/DatabaseConnector.java` соответствуют вашей PostgreSQL.
5. Скомпилируйте проект, добавив `lib/postgresql-42.7.12.jar` в classpath.

## Проверка
Исходники скомпилированы командой `javac` с PostgreSQL JDBC 42.7.12. Подключение к реальной базе и SQL-запросы в этой среде не запускались.
