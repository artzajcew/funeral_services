# Web-клиент «Память»

React-приложение для КР №3. Клиент работает только через REST API и не обращается к базе данных напрямую.

## Запуск с временно подключённым backend

Требуются Node.js 20+, JDK 17+ и запущенный PostgreSQL. Актуальный backend из
ветки `master` временно хранится в `../.local/backend-master` и не попадает в Git.

В первом терминале:

```bash
cd ../.local/backend-master
bash run_api.sh
```

Во втором терминале:

```bash
npm install
npm run dev
```

Откройте `http://localhost:5173`. Запросы `/api` проксируются на
`http://localhost:8080`. Другой адрес backend можно указать в
`VITE_DEV_API_TARGET`. Для production-сборки задайте полный публичный адрес
через `VITE_API_BASE_URL` или обслуживайте frontend и backend с одного origin.

## Проверка и сборка

```bash
npm run build
npm run preview
```

Production-файлы создаются в каталоге `dist/`.

## Роли и маршруты

- Гость: главная, каталог услуг, вход и регистрация.
- Клиент: собственные заявки, создание и изменение заявки, комментарии.
- Менеджер: все заявки, комментарии и изменение статусов.
- Администратор: возможности менеджера, архивирование, услуги, пользователи, аналитика и журнал действий.

Защита маршрутов в интерфейсе нужна для удобства пользователя. Backend обязан независимо проверять токен, роль и принадлежность заявки клиенту.

## REST API

Интерфейс использует маршруты актуального backend:

- `/api/auth/register`, `/api/auth/login`;
- `/api/services`, `/api/services/{id}`;
- `/api/orders`, `/api/orders/{id}`, `/api/orders/{id}/archive`;
- `/api/orders/{id}/comments`;
- `/api/users`, `/api/users/{id}` и административные действия пользователя;
- `/api/analytics`, `/api/audit`.

Ответ входа и регистрации ожидается в формате:

```json
{
  "token": "jwt",
  "user": {
    "id": 1,
    "login": "user",
    "fullName": "Имя пользователя",
    "role": "CLIENT"
  }
}
```

Вместо `token` также поддерживается поле `accessToken`. Списки принимаются как обычный JSON-массив, `{ "content": [] }` или `{ "data": [] }`.
